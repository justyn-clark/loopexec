# LoopExec v0.4.1

This patch improves evidence reporting and couples implementation publication to
matching canonical documentation. LoopExec remains a general-purpose bounded
agentic loop governor, not a project-specific quality certifier.

## Included

- Read-only report timelines, saved failure causes, receipt parsing status and
  bounded missing/damaged-evidence warnings.
- Clear candidate-retention versus convergence and owner-acceptance boundaries.
- Signature-file presence labeled `present_unverified`; explicit attestation
  verification remains separate. Legacy `attested` JSON behavior is preserved.
- Canonical prose/changelog co-change CI gate and generated CLI/JSON field contract.
- Source-bound, allowlisted documentation in all six platform archives, plus a
  standalone documentation archive and SHA256 checksums.
- Official deployed-docs manifest, content and homepage-marker readback before
  release draft creation and again before publication. Missing/stale/unreachable
  documentation blocks publication; there is no alternate-origin override.
- General-purpose acceptance/evidence guidance and an optional creative example.

Targets, numeric domains, direction, tolerance, improvement and patience belong to
workflow configuration. Example scores are fixtures, not runtime/service defaults.
No automatic model calls, budget resets, consumer migrations or promotion are added.

## Compatibility

Existing report exit behavior and convergence exit 10 are unchanged. JSON report
fields are additive. Parsing is not receipt integrity verification, signature
presence is not cryptographic verification, and a retained candidate is not an
owner's acceptance or publication decision.

Every archive retains canonical root documentation paths for README links and a
full `documentation/manifest.json` snapshot bound to source/docs digests. Private
state, handoff notes, logs and secrets are excluded.

## Installation and verification

After publication, with Go 1.26 or newer:

```sh
go install github.com/justyn-clark/loopexec/cmd/loopexec@v0.4.1
loopexec version --json
loopexec demo
```

Or select the OS/architecture archive from
[the release](https://github.com/justyn-clark/loopexec/releases/tag/v0.4.1), verify
`checksums.txt`, extract, and inspect `documentation/manifest.json`.
The [Releases page](https://github.com/justyn-clark/loopexec/releases) is the
authority for whether publication has completed; prepared notes are not proof.

## Validation and limits

CI pins checksum-verified SMALL v1.1.2, including command-summary correction and
narrow, exact-proof-backed local URL source-literal handling.
Historical command receipts remain unchanged; reviewed portable command proof
supports cache-free strict validation without exporting the private cache.

Release CI covers formatting, vet, unit/subprocess/CLI tests, targeted race checks,
legacy/creative/shared-budget proofs and canonical SMALL validation on Linux/macOS.
Windows is cross-built; native Windows runtime remains unverified. Full external
model/provider billing, production containment and project-specific quality are
operator integration responsibilities. Native cross-run objective/policy/owner
decision history is not implemented. Account protections and semantic/visual
docs review are still required; provenance checks cannot prove every sentence.
