# v0.5.0-rc.1

Release candidate for visible, provider-neutral model assignments. This is not
stable v0.5.0 and does not replace v0.4.1 as latest stable. Publication status is
authoritative on [GitHub Releases](https://github.com/justyn-clark/loopexec/releases/tag/v0.5.0-rc.1).

## Model assignments

- Named profiles and per-task builder/critic roles carry provider, model identity,
  reasoning effort, capabilities and human-visible rationale.
- `models plan` previews the selection without running hooks, spending or creating
  run state. Advisory mode leaves the work command unchanged.
- Explicit mode binds whole argv placeholders, requires a reservation hook and
  checks planned/reported model identities. Drift halts retain incurred usage.
- State, reports, typed receipts and attestations include selection. Existing
  records without a selection remain compatible.

See [model assignments](../model-assignments.md) for the adapter contract and
offline proof. Adapter reports are not independent provider attestation. There
is no automatic routing, escalation, model catalog, budget renewal or acceptance
adjustment. Quality targets remain integration-specific.

## Installation and promotion

After publication, pin `go install github.com/justyn-clark/loopexec/cmd/loopexec@v0.5.0-rc.1`
or use the matching checksummed release archive. `@latest` stays on stable.
Consumer adapters must implement explicit argv dispatch, planned reservations and
reported identity; installing the binary alone does not migrate an adapter.
Live consumer/critic acceptance is a separate gate before stable promotion.

Release tooling accepts stable tags and canonical `-rc.N` tags only. RCs are
published as prereleases with Latest disabled. Both channels require the same
matching source-bound documentation bundle and official-origin readback before
draft creation and immediately before publication.
